L1 — sealed judge (brief 1); released as a digest-pinned image at L2. So far: the OCI runtime abstraction (`runtime.py`, brief 1 §2 and A1 item 2). It builds the one command line that runs a candidate container (no `--rm`: removal is the judge's explicit act): `--network=none`, `--read-only` (and Podman's `--read-only-tmpfs=false`, so both runtimes give the same root), `--cap-drop=ALL`, `--security-opt=no-new-privileges`, no mount of any host path, and CPU, memory (swap equal, so none) and process limits from `config.toml`. Docker is admitted only if it reports itself as Docker with a server; Podman only if it is rootless with the cpu, memory and pids controllers delegated. P2 (`harness/pins.py`) runs a probe in that container under every usable runtime and requires at least one. Each denial must be an OS errno: ENOENT or EACCES/EPERM for judge paths, ENETUNREACH for IPv4 and IPv6 TCP and UDP, EROFS for the root. The probe must also see only loopback and the configured cgroup limits. The episode loop (`episodes.py`, brief 1 §2): JSON-RPC 2.0 over the container's stdio, one message per line; per step the judge sends `{t, observation, legal_actions}` and advances the World only on the reply. Every reply is bounded by `[timeouts] step_s` and every episode by `episode_s` from `config.toml`, and a reply line by `reply_bytes`. Every episode is recorded with a termination code: `terminal`/`truncated` when the World ends it; `crash`, `step_timeout`, `episode_timeout`, `invalid_reply`, `illegal_action` when the candidate fails it, after which the container is torn down and the next episode starts in a fresh one. Teardown is `rm -f` (Podman with `--time=0`, so SIGKILL at once), and then the runtime's listing must name nothing; a container still listed is termination `leaked`, counted. P3 (survivorship) and P10 (teardown) run under every usable runtime.
