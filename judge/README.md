L1 — sealed judge (brief 1); released as a digest-pinned image at L2. So far: the OCI runtime abstraction (`runtime.py`, brief 1 §2 and A1 item 2). It builds the one command line that runs a candidate container (no `--rm`: removal is the judge's explicit act): `--network=none`, `--read-only` (and Podman's `--read-only-tmpfs=false`, so both runtimes give the same root), `--cap-drop=ALL`, `--security-opt=no-new-privileges`, no mount of any host path, and CPU, memory (swap equal, so none) and process limits from `config.toml`. Docker is admitted only if it reports itself as Docker with a server; Podman only if it is rootless with the cpu, memory and pids controllers delegated. P2 (`harness/pins.py`) runs a probe in that container under every usable runtime and requires at least one. Each denial must be an OS errno: ENOENT or EACCES/EPERM for judge paths, ENETUNREACH for IPv4 and IPv6 TCP and UDP, EROFS for the root. The probe must also see only loopback and the configured cgroup limits. The episode loop (`episodes.py`, brief 1 §2): JSON-RPC 2.0 over the container's stdio, one message per line; per step the judge sends `{t, observation, legal_actions}` and advances the World only on the reply. Every reply is bounded by `[timeouts] step_s` and every episode by `episode_s` from `config.toml`, and a reply line by `reply_bytes`. Every episode is recorded with a termination code: `terminal`/`truncated` when the World ends it; `crash`, `step_timeout`, `episode_timeout`, `invalid_reply`, `illegal_action` when the candidate fails it, after which the container is torn down and the next episode starts in a fresh one. Teardown is `rm -f` (Podman with `--time=0`, so SIGKILL at once), and then the runtime's listing must name nothing; a container still listed is termination `leaked`, counted. P3 (survivorship) and P10 (teardown) run under every usable runtime. Prediction scoring (`scoring.py`, brief 1 §2): a step reply's prediction naming an undeclared target, of the wrong length, or not summing to one within `len(support)` machine epsilons (a derived bound) ends the episode `invalid_reply` before the World advances, as does a reply carrying NaN or an infinity, which is not JSON. Each declared target is then scored against the World's next observation of its field as −ln of the probability on the realised value: zero scores +inf, counted and never clipped; an omitted target is missing, never imputed. Each episode record carries per target `scored`, `missing`, `infinite`, `finite_sum` and `log_loss` (the finite sum, or the string `+inf`, since JSON has no infinity), with `scored + missing` equal to the episode's steps. P7 witnesses it under every usable runtime. Measured compute (`compute.py`, brief 1 §2): each episode record carries `compute` with `cpu_s`, `wall_s`, `peak_memory_bytes` and `unmeasured_s`, read by the judge from the cgroup the runtime created for the container (found through the container's init process in `/proc` and cut at the component naming the container's id), never from the candidate. The container is sampled after every reply and at the episode's end; its CPU time is partitioned over its episodes, each charged from the previous episode's last sample (or the container's start) to its own. `peak_memory_bytes` is the container's `memory.peak` to that sample. A crashed container takes its cgroup with it: `unmeasured_s` is the wall-clock from the last sample read to the episode's end, and the CPU spent in it is at most the configured CPUs times it. P4 witnesses it under every usable runtime.
